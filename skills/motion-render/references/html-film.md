# html の映像の作り方

新しく作る動画の映像は、1 枚の HTML として書く（音ハメの一打ごとの反応を書けるのは html の映像だけ）。`motion-render kit <work>` が
`<work>/film/kit/` にプレーヤー・音ハメの部品・スタイル・部品・フォント（Noto Sans JP と、手描きの作風用の Klee One）・GSAP とそのプラグイン・three.js・描画の道具（`fx.js`）・場面の秒数・曲の一打の一覧を置くので、
Claude は `<work>/film/index.html` と、場面を書いた `<work>/film/scenes/*.html` だけを書く。描画中はネットワークが遮断されるので、CDN や Google Fonts は使えない。

## ページの骨組み

```html
<!doctype html>
<html lang="ja">
  <head>
    <meta charset="utf-8" />
    <link rel="stylesheet" href="kit/fonts.css" />
    <link rel="stylesheet" href="kit/base.css" />
    <link rel="stylesheet" href="kit/styles.css" />
    <link rel="stylesheet" href="kit/parts.css" />
    <script src="kit/gsap.min.js"></script>
    <script src="kit/timing.js"></script>
    <script src="kit/player.js"></script>
    <script src="kit/beat.js"></script>
    <style>
      /* 暗い平面の作風。ほかの作風では :root と body の色を書かず、<body data-style="paper"> のようにする */
      :root {
        --ground: #0b1622;
        --panel: #12233a;
        --line: #2a4466;
        --ink: #e9f0f7;
        --muted: #8aa0b8;
        --accent: #3ed6c4;
        --danger: #ff6b6b;
      }
      body {
        background: var(--ground);
        color: var(--ink);
      }
      /* …場面ごとのスタイル… */
    </style>
  </head>
  <body>
    <div id="root">
      <!-- 場面をまたいで残るもの（図の全体） -->
      <div id="stage">…</div>
      <!-- 場面ごとのもの（film/scenes/*.html）が、名前の順にここへ入る -->
      <!-- scenes -->
    </div>
    <script>
      // #stage の物の動き。場面のファイルの動きは、それぞれのファイルの film.build に書く
      film.build(function (tl) {
        tl.to("#token", { ...film.spot("#token", "#sts"), duration: 0.8, ease: "power2.inOut" }, film.at("sts", 0.6));
      });
    </script>
  </body>
</html>
```

プレーヤーが用意するもの:

| 名前                                 | 意味                                                                                           |
| ------------------------------------ | ---------------------------------------------------------------------------------------------- |
| `film.build(fn)`                     | フォントの読み込みが終わってから `fn(tl)` を呼ぶ。場面の図の出し入れはこの中に書く             |
| `film.draw(fn)`                      | コマごとに `fn(t)` を呼ぶ。音ハメの動きは全部この中に、時刻 `t` だけから書く（下の「音ハメ」） |
| `film.at(id, 秒)`                    | 場面 `id` の頭から何秒目か（動画の先頭からの秒に直す）                                         |
| `film.end(id, 秒)`                   | 場面 `id` の終わりの何秒前か                                                                   |
| `film.spot(要素, 相手, dx, dy)`      | `要素` の中心を `相手` の中心へ（`dx`・`dy` だけずらして）動かす GSAP の `x`・`y`              |
| `film.arc(tl, 要素, 相手, 秒, o)`    | `要素` を `相手` へ山なりに動かす。o: `dur`（既定 0.9）・`lift`（既定 120px）・`dx`・`dy`      |
| `film.breathe(tl, 要素, id, 秒, 量)` | `秒` から場面 `id` の終わりまで、`要素` を `量`（既定 0.01）だけゆっくり拡大縮小する           |
| `film.typeIn(tl, 要素, 秒, o)`       | `要素` の文字を 1 文字ずつ下から立ち上げる。o: `dur`（既定 0.5）・`stagger`（既定 0.04）       |
| `film.light(tl, 要素, 秒, o)`        | 部品の `step`・`card` を `秒` に光らせる。o: `off`（消す秒）・`dur`（既定 0.35）               |
| `film.ticks(要素, o)`                | 部品の `ruler` に目盛りを付ける。o: `step`（間隔）・`label`（既定 `"{v}"`、`""` で無し）       |
| `film.caption(tl, 要素, id, 秒)`     | 字幕を `秒` に出し、場面 `id` の終わりの 0.25 秒前までに消す                                   |
| `section.scene`                      | その場面の間だけ見える。`#stage` のように section の外に置いたものはずっと見える               |

## 表現の道具

図と文字だけの映像は薄く見える。豊かさは、物の質感、奥行き、動きの緩急、場面の切れ目の無さから来る。
`kit` には、HTML と SVG のほかに、次の道具がある。どれを使うかは、見せたい物の性質から決める。全部を使う必要は無い。

| 道具                                    | 読み込み                                                | 向いている物                                                        |
| --------------------------------------- | ------------------------------------------------------- | ------------------------------------------------------------------- |
| SVG と GSAP                             | `kit/gsap.min.js`                                       | 図、線、文字の配置。読ませる物                                      |
| GSAP のプラグイン                       | `kit/gsap/<名前>.min.js` と `gsap.registerPlugin(名前)` | 下の表                                                              |
| Canvas 2D と `fx`                       | `kit/fx.js`、`fx.canvas(セレクタ)`                      | 数百の粒、手描きの線、斜線の塗り、ノイズの流れ、紙や粒子の質感      |
| three.js（`window.THREE`）と `fx.three` | `kit/three.min.js` と `kit/fx.js`                       | 立体の物、光と影、カメラの移動、分解図。3D の上の文字は HTML で置く |
| モーションブラー（`script.json`）       | `"motionBlur": 2〜8`                                    | 速く動く物。1 コマに複数の時刻の絵を重ねて、動きの残像を作る        |

GSAP のプラグイン（`kit/gsap/`）:

| 名前                                                     | できること                                               |
| -------------------------------------------------------- | -------------------------------------------------------- |
| `SplitText`                                              | 文字・語・行に分けて、別々に動かす                       |
| `DrawSVGPlugin`                                          | 線が描かれていく                                         |
| `MorphSVGPlugin`                                         | 1 つの形が別の形に変わる                                 |
| `MotionPathPlugin`                                       | 道筋に沿って動き、向きも道筋に合わせる                   |
| `CustomEase`・`CustomWiggle`・`CustomBounce`・`EasePack` | 自分で描いた緩急、揺れ、弾み                             |
| `ScrambleTextPlugin`・`TextPlugin`                       | 文字が入れ替わりながら決まる、書き換わる                 |
| `Physics2DPlugin`                                        | 速さと重力で飛ぶ                                         |
| `Flip`                                                   | 並びや大きさが変わったとき、前の位置から新しい位置へ動く |

`kit/fx.js` が用意するもの（すべて入力だけで値が決まる。`film.draw` の中で時刻 `t` から呼ぶ）:

| 名前                                      | 意味                                                                                          |
| ----------------------------------------- | --------------------------------------------------------------------------------------------- |
| `fx.rand(seed)`                           | シード付きの乱数の関数。`Math.random` の代わり                                                |
| `fx.noise(x, y, z)`・`fx.fbm(x, y, z, n)` | 滑らかなノイズ（-1〜1）と、細かさを重ねたノイズ。`t` を座標の 1 つに入れると流れる            |
| `fx.spring(t, t0, o)`                     | `t0` に放したばねの位置（0 → 1、行き過ぎて戻る）。o: `freq`（Hz）・`damp`（1 で行き過ぎない） |
| `fx.follow(t, [[t0, 値], …], o)`          | 目標が何度変わっても、行き過ぎずに次の目標へ移る値                                            |
| `fx.boil(点の列, t, 幅, 回数)`            | 手描きの線のふるえ。1 秒に `回数` だけ形が変わる                                              |
| `fx.canvas(セレクタ)`                     | 画面と同じ大きさの canvas の 2D の描き手。コマごとに全体を描き直す                            |
| `fx.grain(ctx, t, 量)`                    | 粒子の質感をコマごとに重ねる                                                                  |
| `fx.three(セレクタ, o)`                   | three.js の描き手・場面・カメラ。`film.draw` で物とカメラを `t` から置き、`render()` を呼ぶ   |
| `fx.project(位置, カメラ)`                | 3D の点が画面のどこに映るか（px）。3D の物に HTML の文字を添える                              |

### 豊かに見せる

見る人に何が起きるかと、それを作る手段の組を書く。形や数値は内容から決める。

- **途切れない**: 前の場面の物が、大きさ・形・色を変えて次の場面の物になる。形が画面を満たして、その内側が次の場面になる。
  場面の切れ目を、物の変化で見せる（「場面を物でつなぐ」）
- **重さと手応え**: 物はばねで止まる。軽い物は行き過ぎて戻り、重い物は行き過ぎない。出る物は速く、読ませる物はゆっくり着地する。
  等速の動きは機械に見える
- **重なり**: 主の動きに、小さな従の動きを少しずつ遅れて重ねる。全部が同時に止まらない。先端が先に伸び、後端が追う
- **奥行き**: 手前と奥を別の層にして、カメラが動くと層ごとに違う速さで動く。立体が要る物は three.js で、光の向きを決めて置く
- **カメラの意志**: その時の主役が画面を満たすまで寄る、主役を追う、あえて動かさない。カメラが何を見せたいかを決めてから動かす
- **質感**: 平らな塗りだけにしない。線の揺れ、斜線の重ね、紙や粒の目、光の当たり方で、物に素材を持たせる。質感は全体で 1 つの系統に揃える
- **文字の出方**: 文字を語や字に分け、意味に合った順と速さで出す。線の下から立ち上がる、入れ替わりながら決まる、書かれていく
- **速さの見え方**: 速い物は残像（モーションブラー）で速さを見せる。衝撃の一瞬だけ、画面全体に強い変化を入れる。常には入れない
- **本物を動かす**: 仕組みや過程は、それらしい絵でなく、本当に計算して動かす（下の「仕組みを本物で見せる」）。数字は本物の値で数え上げる

描き方の決まり:

- canvas と three.js も、`film.draw` の中で `t` だけから全体を描き直す。前のコマの状態を使わない
- 物理や粒の動きは、式で `t` の位置を出すか、0 から `t` まで毎回計算し直す。前のコマから積み上げない
- 重い描画（大きな 3D、画面全体のシェーダ）は書き出しを遅くする。モーションブラーは書き出しの時間を枚数倍にする。
  効く所に絞って使う

## 演出

この節に書くのは演出の意図だけである。技法・形・色・動きの速さ・構成は、ここには書かない。それらは毎回、内容から想像して決める。
決まった答えをなぞった映像は、内容が正しくても退屈になる。

この映像は、説明のスライドではなく、主題を高く見せる 1 本の作品として作る。機能や手順を順に並べた映像でも、手法の見本を並べた映像でも、
型に中身を流し込んだ映像でもない。

### 必然に見せる

音と絵を合わせる仕組みは、それだけでは格好よさを生まない。合わせた瞬間が「その場で、曲としても絵としても、そうなるしかなかった」
ように見えたとき、格好よくなる。見せたい演出は削らない。演出の 1 つ 1 つに、そうなる理由を、話と曲の両方に先に仕込む。

合わせた瞬間が必然に見えるのは、次の 3 つが揃うとき。

1. **原因**: その音を出していそうな物が、画面にある。もっともらしい原因があるとき、音と絵は話の一部に見える
2. **告知**: 見る人が、いつ・何が起きるかを先に知って待っている。快は頂点だけでなく、頂点を待つ時間に生じる
3. **引き**: 直前が静かで、合わせていない時間がある。高い所は、低い所があって初めて高く見える

どれかが欠けた演出は、取って付けたものに見える。

### 遊び

毎回同じ答えに収束させない。最初に思いついた見せ方は、ほかの多くの動画でも思いつく見せ方である。

- その題材でしか成り立たない見せ方を探す。題材を入れ替えても成り立つ見せ方なら、まだ探し足りない
- 見る人の予想を、話の必然の中で、良い方向に一度は外す
- 前に作った動画と同じ構成・作風・動きに寄せない

### 演出の表

`plan.md` に、入れる演出ごとに 1 行の表を書く。これがこの映像の演出意図になる。

| 演出 | 話の出来事 | 原因 | 告知 | 引き | 曲の理由 |
| ---- | ---------- | ---- | ---- | ---- | -------- |

- **演出**: 入れる演出を全部並べる。依頼で頼まれた演出と、この映像に置くと決めた山場。この列は削らない
- **話の出来事**: その瞬間に、題材の中で何が起きるか。元に戻らない出来事ほど強い
- **原因**: 画面の何が、その音を鳴らしているように見えるか
- **告知**: 見る人がいつ、何によってそれを予見するか
- **引き**: 直前に何を減らすか
- **曲の理由**: 曲としてなぜそこでそうなるか

空欄が出たら、演出を削らず、話の側を作り直して埋める。山場でない行は、告知と引きを空けてよい。
曲を並べた後に、もう一度この表に戻る（「音ハメ」の「曲が届いたら」）。

### 演出を設計する順

1. **主題の中の力と出来事を見つける。** 何が力を出し、何が起きたら戻らないのか。題材が抽象的なら、その仕組みが実際に働いている
   具体的な場面を 1 つ想像して舞台にする。仕組みの図解を舞台にしない
2. **問いを置く。** 冒頭で、見る人が何を待つのかを決める
3. **山場を決める。** 山場の数も形も内容から決める。静かな内容なら、山場を置かなくてよい
4. **演出の表を埋める。**
5. **強さの曲線を引く。** 場面ごとに、絵と曲の強さを書く。最大の瞬間を最重要の出来事に先に固定し、そこから逆算する。
   手前で同じ強さを使わない。最大の強さは山場まで取っておく。山場の後に、余韻を置く
6. **一打の役を決める**（「音ハメ」の「一打を役に割り当てる」）
7. **書く前に決める**（次の節）

### 書く前に決める

「作る前に決めること」のコメントに、次を書く。

1. **一行の発想**: 全場面を貫く考えを 1 文で。演出はすべて、この発想の内側から生む
2. **狙う反応**: 見終わった人に浮かぶ一言を 1 文で
3. **素材と態度の語、避ける語**: 見た目の性格を、素材・質感・態度の語で書き、避ける語も書く。
   依頼の言葉は性格の手がかりとして読み、描く物にそのまま変えない。主題からすぐ連想される定番の絵は、避ける語に入れる。
   曲は SKILL.md の「曲の作風」のとおり、実在のジャンルを 1 つ選んで、その語法で書く
4. **見せ場**: 効果の名前を使わずに言える、際立った瞬間をいくつか。凡庸な多くの動きより、際立った少しの瞬間

### 意図

1. 1 場面に 1 つの考え。場面に間を残す
2. 見る人の目が、どこを見ればよいか迷わない。主役が画面を占め、空いた所に小さな物を浮かべない
3. 画面の文字は、見る人に向けた言葉だけ。説明は語りがする。作り手の都合の文字（手法や区間の名前、飾りのラベル）は出さない
4. 次の場面は、前の場面の物から生まれる。見た人が「次がそこから来たのは当然だ」と思うつなぎにする
5. 動きには重さと意図がある。機械的に動く物、理由なく弾む物は、作り手の手癖に見える
6. 物ごとに着く時刻をずらし、主の動きに従の動きを重ねる。全部が一斉に動いて一斉に止まらない
7. 強さは、効果の足し算でなく、対比と構図で出す。画面を飾る効果は、話の中にその現象があるときだけ使う
8. 完全な静止は、勝ち取った瞬間にだけ使う
9. 音が無くても話が伝わる
10. 世界の状態を変え続ける。数拍ごとに、話の中の何かが目に見えて進む
11. 出した物は、後で使う。使わない物は出さない。見る人が何か分からない形は置かない
12. 語りが言う出来事は、語りと同時に絵で見せる。冒頭の問いの答えは、語りだけでなく絵で見せる
13. 場所や視点が変わるときは、変わる途中を見せる。画面全体の色や明るさの変化には、話の理由がある
14. 速さや力は、主役そのものの動きで見せる。数字の表示に任せない。数字は、その瞬間に大事な物だけを見せる
15. 終わりは、答えが出た後に、受け止める間を残して閉じる。最後の一打は答えの後に来る

### 美術

- **格子**: 端を揃える基準を決め、すべての要素をそれに従わせる。止まっている物は安全域（左右 144px、上下 81px）の内側に置く（`check` の決まり）
- **文字**: 役目ごとに階層をはっきり付ける。大きな語は短く、思い切って大きく。文字は組んだ物として動かす
- **色**: 色は意味を運ぶ。強調は希少なほど効く
- **コマ**: 最初のコマから完成した絵にする。どこで一時停止しても、1 枚の絵として成り立つ構図にする

### 見直し

作り手は、自分の作品を判定しない。見直しは 1 回だけ行い、それで仕上げる。

1. 書き出した MP4 から、要所のコマを 1 枚に並べる: `motion-render sheet <work> <mp4> <work>/sheet.png`（並びの説明は `sheet.txt`）
2. 制作の経緯を知らないサブエージェント（批評役）に、`sheet.png` と `sheet.txt` と語りの原稿と次の問いだけを渡し、答えを
   `<work>/critique.md` に書かせる。何を狙ったか、何を直したかは伝えない
3. 答えの悪い順の 3 つまでを直し、もう 1 回だけ書き出して終える。2 回目の批評はしない

問い:

1. 一番強かった瞬間はどこか。来る前から、それを待っていたか
2. 取って付けたように見えた所はどこか
3. 型どおりの映像、スライド、画面の録画に見えるコマはどれか
4. 物が多すぎるコマ、何か分からない物や小さな物が浮いているコマはどれか
5. 前の場面とつながっていない切り替えはどこか
6. 悪い順に 3 つ挙げると何か

Agent ツールが無いときは、自分で同じ問いに答える。90 秒の動画は、見直しを含めて 30〜40 分で仕上げる。これを大きく超えて試行錯誤しない。

## 音ハメ

曲（`motion-render score` が並べた曲）に映像を合わせる。新しく作る動画では必ず入れる。どう合わせるかは内容から決める。

基準は、ロケットの打ち上げを見せた 90 秒の動画。そこでは、一打で動く物すべてに一打で動く理由が話の中にあり、
曲が止まったのは話の中で時間が 0 になった 1 回だけで、山場は溜まっていた物が満ちた結果として来た。これを下回らないように作る。
形は写さない。写すのは、理由のある物だけが動き、山場が満ちた結果として来るという働きである。

理由の無い物を一打ごとに跳ねさせると、合わせるために入れた動きに見える。映画音楽で、画面の動きを音が一つ残らずなぞる書き方を
「ミッキーマウジング」と呼び、多用すると安っぽく見えるとされるのと同じである。

### 時間を決める順番

語り → 映像 → 曲。語りが場面の秒を決め（`narrate`）、映像はその秒の中で山場を作り、曲は山場に合わせて並べる。
曲の都合で語りを止めない。区間の頭（`section`）はすでに小節の頭にあり、一打の一覧（`beat.hits`）は曲から測った実際の時刻。

### 山場の働き

山場を置くなら、山場は次の働きを持つ。どんな形で実現するかは、出来事の質から想像する。

- **山場の瞬間**: 画面全体が一打で変わる。変わり方は出来事の質に合わせる
- **山場の区間の一打**: 話の中で力を出している物（以下「動力」）が、一打に応える。応え方は動力の性質から決める
- **溜め**: 一打ごとに、話が元に戻らない形で一段進み、満ちた所で山場が来る
- **止め**: 曲が止まるなら、画面の世界も同じ理由で止まる
- **2 回目の山場**: 1 回目の繰り返しに見えないよう、何かを替える
- **最後の一打**: 1 本の答えが残る

道具が測る条件（`sync` と `score` の検査。これを満たさないと書き出しが不合格になる）:

- 山場と最後の一打の瞬間に、画面全体の変化が、ふだんの大きな変化の 4 倍以上ある。山場の無い動画では、
  最後の一打は測って報告するだけで、合否には使わない（静かな動画の終わりを、取って付けた大きな変化にしない）
- 山場の区間のキックの 8 割で、画面のどこかが動く。反応は 8 分音符の長さ（`30 / beat.bpm` 秒）以内に収める。
  動力が画面の小さな一部だと、動いても測れない
- 曲を止めるのは 1 本に 1 回まで

意図:

- 一打で動かさない物を決める。読ませる物と、自分のリズムを持つ物は、一打で跳ねさせない
- 1 つの一打を 2 つの物に当てない
- 強さに階層を付ける。画面全体を使うのは、山場の瞬間・止め・最後の一打だけ
- 拍に合わせるのは大事な瞬間だけ。続いている動きは連続して動かし、拍ごとに刻まない
- 語りに対応する画面の文字は、拍ではなく語りの句と間に合わせる
- 山場の頭は絵と音に渡す（SKILL.md の「語りの決まり」）

### 読みやすさの決まり

`check` が止める決まりと、読めなくなる原因を書く。

- 読む物はカメラの外（`#cam` の外）に置き、揺らさず拡大しない
- 大きな文字（40px 以上）は、2 秒以上かつ 4 文字あたり 1 秒以上残す（`beat.words` を使うとこれを満たす）
- 5px 未満の震えは使わない（位置がずれて見える）。画面全体の明滅は 1 秒に 3 回まで（光過敏への配慮）
- 画面より大きな要素は `check` が「画面で切れている」と止める。背景はカメラの外に画面いっぱいで置く

### 書き方: `film.draw` と `kit/beat.js`

音ハメの動きは、index.html の `film.draw(function (t) { … })` 1 つに書く。`t` だけから、その瞬間の値を全部計算して書く。

- GSAP のタイムラインに音ハメの動きを書かない。GSAP は動きの開始値を覚えて、巻き戻すとそこへ戻すので、
  同じ値を 2 つの動きが書くと、書き出しと静止画で絵が変わる（`check` が「changes after seeking back」で止める）
- 1 つの値を書くのは 1 か所だけ。値は「基準の値 + 一打ごとの上乗せ」で作る
- 場面の図の出し入れは今までどおり `film.build` でよい。ただし同じ要素の同じ値（`transform` など）を、`film.draw` と GSAP の両方で書かない

`kit/beat.js` が用意するもの（すべて時刻 `t` だけから値を返す）:

| 名前                                                            | 意味                                                                                                                      |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `beat.pick({ k, from, to, min })`                               | 曲の一打の一覧。`k` は `"kick"`・`"snare"`・`"rim"`・`"ghost"`・`"hat"` かその配列、`from`〜`to` は秒、`min` は強さの下限 |
| `beat.pulse(list, t, dur)`                                      | `list` の一打のコマで 1、`dur` 秒かけて 0 に戻る値（一打の強さを掛けてある）。基準の値に足す                              |
| `beat.since(list, t)`                                           | 直前の一打から何秒たったか（まだ無ければ Infinity）。一打ごとに一度走る物に使う                                           |
| `beat.steps(list, t, dur)`                                      | 一打ごとに 1 段ずつ増える値（0 → `list.length`）。溜めの寄り、メーター                                                    |
| `beat.snap(秒)`                                                 | その秒に一番近いキックかスネア（半拍以内）、無ければ一番近い拍の時刻。場面の動きの開始を曲に乗せる                        |
| `beat.track([[t0, a, b, dur, ease], …])`                        | 動きの並び。`(t, 始めの値)` を渡すと、`t` までに始まった最後の動きの値を返す                                              |
| `beat.shake(t, t0, amp, dur)`                                   | `t0` の一打からの揺れ `{x, y}`（`amp` px から減衰、既定 0.55 秒）                                                         |
| `beat.flash(t, times, peak, dur)`                               | `times` の各時刻の閃光の不透明度（既定 0.85、0.18 秒）                                                                    |
| `beat.words([{ el, t, soft }])`                                 | 大きな文字の描き方を返す（`film.draw` の中で `words(t)`）。中の `<b>` は下線として左から引かれる                          |
| `beat.place(el, { x, y, s, sx, sy, r, o })`                     | 位置・大きさ・回転・不透明度をまとめて書く                                                                                |
| `beat.alpha(el, a)`                                             | 不透明度と表示をまとめて書く（0 で非表示）                                                                                |
| `beat.mix(色1, 色2, p)`                                         | 2 色の間の色                                                                                                              |
| `beat.ease`・`beat.prog(t, t0, d)`                              | 緩急（`out2` など GSAP と同じ形）と、`t0` から `d` 秒の進み具合（0〜1）                                                   |
| `beat.drops`・`beat.end`・`beat.sections`・`beat.bar`・`beat.E` | 全開の時刻、最後の一打の時刻、区間の一覧、1 小節の秒、一打を早めて見せる秒（0.008）                                       |

書き方の形（API の使い方だけを示す。何を動かし、どう応えるかは内容から決める）:

```html
<script>
  var SNAP = Math.min(0.2, 30 / beat.bpm); // 反応は 8 分音符の長さ以内に戻す
  var kicks = beat.pick({ k: "kick", from: beat.drops[0], to: film.at("calm") }),
    build = beat.pick({ k: "kick", from: film.at("build"), to: beat.drops[0] - beat.bar });
  film.draw(function (t) {
    // 値は t だけから計算する。「基準の値 + 一打ごとの上乗せ」で作り、1 つの値を書くのは 1 か所だけ
    var grown = beat.steps(build, t) / Math.max(1, build.length); // 一打ごとに一段進み、戻らない
    var hit = beat.pulse(kicks, t, SNAP); // 一打のコマで 1、SNAP 秒で 0 に戻る
    beat.place("#drive", { s: 1 + 0.3 * hit });
    beat.place("#progress", { sx: grown });
  });
</script>
```

場面の図の出し入れ（`film.build` の GSAP）は、開始の秒を `beat.snap` に通して曲に乗せる:
`tl.from("#card-a", { y: 40, autoAlpha: 0, duration: 0.3 }, beat.snap(film.at("route", 1.2)))`。
GSAP で出し入れする物は `opacity` でなく `autoAlpha` で隠す（隠れた物が配置の確認で見えている扱いにならない）。

### 曲が届いたら

`motion-render score` は、並べた曲の目立つ瞬間（急に抜ける、戻る、単発の一打）を `moment:` の行に、時刻と、そこで始まる区間と一緒に出す。
聞く人はこの瞬間に気づく。曲だけが何かをして絵が応えない瞬間は、取って付けた音に聞こえる。

- `moment:` の行ごとに、演出の表に行を足し、話の出来事を当てる。区間の頭（`start of …`）でない瞬間ほど、当てる出来事を探す
- 当てる出来事が無ければ、その小節を差し替えて、目立つ瞬間そのものを消す（`score` の `bars` を直す）
- 当てた出来事は `beat.snap` で一打の時刻に置く

### 一打を役に割り当てる

一打の一覧は `motion-render score` の後に `kit/timing.js` に入り、`build` が毎回書き直す。曲を並べ直しても映像は書き直さない。

- 役は時間で決める: `beat.pick({ k: "kick", from: film.at("場面"), to: DROP1 }).slice(0, N)` で、その場面の最初の N 打を N 個の物に当てる
- 音と絵の対応は、題材の中の実際の構造（数、順序、左右、遠近）に合わせる
- 山場の前は進める一打（打たれたら元に戻らない変化）、全開は戻る一打（動力の脈動）。溜めた物が満ちた瞬間を山場にする
- 一打の役は、話の段階ごとに替える。同じ反応を 1 本を通して繰り返さない。1 つの一打を 2 つの物に当てない
- 曲が鳴っていない区間（止め、無音の小節）では一打の反応を出さない。単発の一打だけを決めの動きに使う

## 作る前に決めること

`index.html` を書き始める前に、ページの先頭に HTML のコメントで次を書く。依頼文と内容から決め、利用者には聞かない。
場面を書くたびにこのコメントに照らして、外れたものを直す。

- **一行の発想・狙う反応・素材と態度の語と避ける語・見せ場**（「演出」の「書く前に決める」）
- **作風と配色**: 内容から決める（下の「作風」）。1 本の中で変えない
- **文字の役割**: 役目ごとの大きさと太さ
- **動きの性格**: 出る・移る・消えるの緩急と、読ませる間。同じ役割の物には同じ動きを使う

## 絵コンテと秒の計画

場面を書き始める前に `<work>/plan.md` を書く。場面を手分けして書くときの共通の指示書であり、効果音を先に作る元でもある。
秒は `timing.json` の場面の長さに収める。場面ごとに次の 5 つを書く。

```markdown
## <場面 id>（<秒>）
- 見せるもの: <この場面で起きる出来事と、画面の主役>
- 部品: <使う形>
- 動き: <秒> <動き> ／ <秒> <動き> …
- 効果音: <秒> <prompt> <duration> …
- 残る物: <場面をまたぐ物の、入るときと出るときの状態>
```

- 動きの秒は、その動きに渡す `film.at(場面, 秒)` の秒にする。書き手はこの秒を変えない
- 場所は id で指す（「`#st-mix` の真下」）。座標を書くのは、画面の割り当て（どの帯に置くか）だけにする。
  中身の大きさで位置が変わる物（並んだカードの 2 枚目以降）を座標で書くと、書き手の計算とずれる
- 残る物（`#stage` の物）は、場面の頭と終わりの状態（位置・大きさ・見えるか）を書く。
  まとまりの境目の場面ほど詳しく書く。境目で物が飛ばないようにするため
- 効果音は `prompt` と `duration` まで書く。そのまま `script.json` の `sfx` に写す

## 作風

作風は内容から決める。決まった割り当ても既定の作風も無い。依頼文に見た目の指定があれば従う。利用者には聞かない。

`kit` には、次の作風が用意してある。どれかを選んでもよいし、どれも選ばず、内容に合う配色と質感をページで自分で決めてもよい
（`data-style` を付けず、`:root` に色を書く）。

| 作風           | `data-style` | 見え方                                                                   |
| -------------- | ------------ | ------------------------------------------------------------------------ |
| 暗い平面       | （付けない） | 暗い地に、色を絞った平らな図                                             |
| 紙と鉛筆       | `paper`      | 白い紙に、揺れる鉛筆の線と斜線の陰、黄土色の強調と蛍光ペン、手書きの文字 |
| 色鉛筆         | `crayon`     | 暖かい紙に、太くやわらかい線と、紙の目が透ける塗り                       |
| 設計図         | `blueprint`  | 青い地に白い方眼と、揺れないきれいな白い線                               |
| 紙コラージュ   | `collage`    | クラフト紙の上に、破った色紙をテープで貼る                               |
| ホワイトボード | `whiteboard` | 白い板に、マーカーの線と手書きの文字                                     |

`data-style` を付けると、地・面・線・文字の色（`--ground` `--panel` `--line` `--ink` `--muted`
`--accent` `--danger`、蛍光ペンの `--mark`、塗りの `--tint-1`〜`--tint-4`）、紙の目や方眼、文字の書体が決まる。ページでは色をこの変数で書き、別の色を足さない。
紙の目と方眼は `#root` の後ろに描かれ、`check` は文字の色の差を `--ground` や面の色に対して測る。

作風の部品（どの作風でも同じ名前で使え、作風ごとに見え方が変わる）:

| クラス・変数                   | 使うもの                                                                                                                                                          |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `drawn`                        | カード・枠。手で引いた枠線を描く。`style="--fill: var(--tint-2)"` で中を塗る。中の文字は揺らさない                                                                |
| `sketch`                       | 線の図（矢印・アイコン・グラフの線の `<svg>`）。線が手描きのように揺れる。文字を持つ要素には付けない                                                              |
| `hatch`                        | 棒グラフの棒や図形の陰。`color` の色の斜線で塗る。上に文字を置かない                                                                                              |
| `url(#mr-hatch)`               | `<svg>` の図形（人の胴、箱）の `fill`。`--line` の斜線で塗る。`url(#mr-hatch-accent)` は `--accent` の交差した斜線。図形には `sketch` も付ける                    |
| `marker`                       | 見出しや大事な語の後ろに蛍光ペンを引く。GSAP で `{ "--mark-x": 0 }` から `{ "--mark-x": 1 }` へ動かすと左から引かれる。上の文字は `--ink` のままにする            |
| `tooth`（`crayon`）            | 文字のない図形を色鉛筆で塗ったように、紙の目を透かす                                                                                                              |
| `cutout`・`taped`（`collage`） | 紙片。破れた縁と影を付ける。`--fill` で紙の色（`--tint-1`〜`--tint-4`）を選び、`taped` で上にテープを貼る。縁が 20px ほど外へ出るので、紙片の間を 40px 以上あける |

- 手描きの線は、プレーヤーが 1 秒に 8 回描き直して小さく揺らす（同じ時刻はいつも同じ絵になる）。
  線を描き足すときは今までどおり `stroke-dashoffset` で引く
- 紙コラージュの紙片は GSAP の `rotation` で -2〜2 度傾け、場面に入るときは上から置くように落とす
- ホワイトボードと紙と鉛筆では、説明の順に線と文字を書き足していく（1 枚の板・1 枚の紙を最後まで使う）
- 作風が紙の目や揺れを足すので、ページでは模様や影を足さない
- `Klee One` の太字は 600 まで。`font-weight: 700` は 600 で描かれる

## 部品

`kit/parts.css` に、解説の映像でよく使う形がある。内容に合うときに使う。使うときは、場面では中身と秒だけを書き、形を一から書かない。
色はページの変数（`--panel` `--line` `--ink` `--muted` `--accent`）から取るので、どの作風でも使える。
手描きの作風では `step`・`card` に `drawn` も付ける（線は作風が描き、部品は光らせるだけにする）。

| 部品         | 書き方                                                                                                                                                                                                                                                                                                   | 動かし方                                                                 |
| ------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 工程の列     | `<div class="steps layer-card" style="left:…; top:…">` の中に `<div class="step"><svg>…</svg><span>原稿</span></div>` を並べる                                                                                                                                                                           | `film.light(tl, "#s-script", 秒, { off: 秒 })`                           |
| カード       | `<div class="card layer-card" style="position:absolute; left:…; top:…">` に `<span class="card-title">` と `<span class="card-body">`                                                                                                                                                                    | `film.light` で光らせる。出し方は自分で書く                              |
| 時間のレーン | `<div class="lanes layer-card" style="--from: 0; --to: 20; left:…; top:…; width:…">` に `<span class="lane-name">語り</span><div class="track">…</div>` を組で並べる。`track` の中に `<div class="seg" style="--at: 2; --len: 5.8"><span>場面 1</span></div>` と `<i class="pin" style="--at: 7.5"></i>` | `seg`・`pin` を GSAP で出す（`scaleX` で伸ばす、`scale` で跳ねる）       |
| 目盛り       | `<div class="ruler layer-line" style="--from: 14; --to: 26; left:…; top:…; width:…">`                                                                                                                                                                                                                    | `film.build` の中で `film.ticks("#ruler", { step: 2, label: "{v} 秒" })` |
| 字幕         | `<p class="caption layer-caption">…</p>`                                                                                                                                                                                                                                                                 | `film.caption(tl, "#cap-flow", "flow", 秒)`                              |

- `seg` と `pin` の位置は、`lanes` の `--from`〜`--to` を `track` の幅に当てて決まる。秒でも、ほかの単位でもよい
- 1 本の `track` の中で `seg` と `pin` を重ねない（`check` が重なりとして出す）。印は別の `track` に置く
- 大きさは変数で変えられる: `--step-w`（工程の幅）、`--steps-gap`、`--lane-h`（レーンの高さ）、`--ruler-pad`、`--tick-w`（目盛りの文字の幅）

## 配置の決まり

`motion-render check` はこれを破った所を見つけて止める。最初から守って書く。

1. **関係のあるものは、親子にしてレイアウトで並べる。** カードの中身（見出し、説明、チェック項目、
   中に入るチップ）はカードの子要素にし、`display: flex` / `grid` と `gap` で並べる。
   画面全体の座標（`position: absolute; left: …px`）で 1 つずつ置くのは、図の大きな部品（カード、
   字幕、流れ図）だけにする。子の箱（アイコン、下線）を持つ要素の文字は `<span>` で包む。
   文字を直に持つ要素は `check` が文字の範囲で測るので、文字の外にある子がはみ出しと出る
2. **印は、判定する相手の中に置く。** ✕・✓・バッジ・番号は、それが付く要素の子にする
   （`<div class="chip">OIDC トークン<span class="mark">✕</span></div>`）。2 つの要素の間の
   空いた所に浮かせない
3. **重なり順は役割で決める。** 位置を持つ要素には `kit/base.css` の層のクラスを 1 つ付ける。
   HTML に書いた順番に頼らない

   | クラス          | 使うもの                       |
   | --------------- | ------------------------------ |
   | `layer-bg`      | 背景、グラデーション           |
   | `layer-card`    | カード、パネル、枠             |
   | `layer-line`    | 矢印、つなぐ線、グラフの補助線 |
   | `layer-chip`    | 動くチップ、トークン           |
   | `layer-mark`    | ✕・✓・強調の輪                 |
   | `layer-caption` | 字幕                           |

4. **チップの行き先は `film.spot` で決める。** 止まる位置は、カードの中に収まるか、どのカードとも
   重ならない所にする。カードの枠線をまたいで止めない。SVG の要素（アイコンの `<svg>`、図の中の図形）も
   `film.spot`・`film.arc` で動かせる
5. **箱は親の中に収める。** 親より大きくなりそうな中身は、文字を短くするか親を広げる。
   はみ出しを `overflow: hidden` で隠さない
6. **前の場面の残りを片付ける。** 次の場面で使わない部品は、場面の頭で消すか薄くし、新しい部品と
   同じ場所に重ならないようにする

意図した重なり（グラフの基準線が棒を横切る、軸のラベルが目盛りの外に出る、わざと斜めに押す判子）は、
その要素に `data-layout-ok` を付けると `check` が数えない。間違いを黙らせるためには使わない。

## 場面を分けて書く

場面は `film/scenes/<番号>-<名前>.html` に、続いた場面のまとまりごとに書く。プレーヤーが開くとき、
`index.html` の `<!-- scenes -->` の行に、ファイル名の順で差し込まれる。1 つのファイルには、
その場面の `<style>`、`<section class="scene">`、`<script>film.build(…)</script>` を書く。

```html
<style>
  #flow .steps { left: 260px; top: 180px; }
</style>
<section class="scene" id="flow">…</section>
<script>
  film.build(function (tl) {
    film.light(tl, "#flow-s1", film.at("flow", 1.6));
  });
</script>
```

- 音ハメの層（index.html の `film.draw`、カメラ、山場の切り替え、大きな文字）は分けない。Claude が index.html に 1 つで書く。
  場面のファイルは、その場面の図の出し入れだけを書き、音ハメの層が動かす要素の値を書かない
- id はページ全体で 1 度だけ。場面の id を頭に付ける（`#flow-s1`）
- スタイルは `#場面id` で始める。ほかの場面に効かせない
- `index.html` は書き換えない。`#stage` の物は自分の場面の秒の間だけ動かし、場面の終わりに plan.md の状態にする
- 自分のファイルだけを `motion-render check <work>/film <ファイル名>` で調べる。ほかのファイルを入れずに、
  自分の場面の秒だけを調べる。`layout ok` になり、`runner` の行が出なくなるまで直す
- 静止画は 1 回だけ、自分の場面の中ほどの秒で見る。全体の見た目は、全員が返ったあとに Claude がまとめて見る

まとまりは続いた 2 場面ずつにする（最大 7）。書き手の時間は、手引きを読む決まった時間と、場面の数に比例する時間の和なので、
1 人あたりの場面を減らすほど全員がそろって早く返る。ベンチマーク（14 場面）では、3〜4 場面ずつの 4 人だと最も遅い 1 人が
8 分 40 秒かかり、2 場面ずつの 7 人だと 5 分 15 秒だった（ほかの 6 人は 2 分 24 秒〜3 分 45 秒）。
書き手 1 人あたり 12〜15 万トークンを使うので、7 人で 1 本あたり約 90 万トークンになる。

サブエージェントに頼むときは、1 つのまとまりに 1 つ、次を渡す。

```
<work>/film/scenes/<番号>-<名前>.html に、場面 <id>, <id>, … を書いてください。
- 先に読むもの: <skill>/references/html-film.md、<work>/plan.md、<work>/film/index.html、<work>/timing.json
- plan.md の各場面の「動き」の秒と「残る物」の状態を守る。index.html は変えない

- 静止画は 1 回だけ見る。plan.md に無い細部は自分で決め、問い返さない
- 返すもの: ファイル名、plan.md から変えた秒（無ければ「なし」）、直しきれなかった問題
```

## 動き

動きの速さと緩急は、内容の速さと温度から決める。同じ役割の物には同じ動き方を使い、1 本を通して動きの性格を揃える。

- 1 場面 1 つの出来事。図が動き終わってから字幕を出す。字幕は場面の終わりの 0.25 秒前に消す
- 読ませる物は、読み終えられるだけの間を残す
- 秒数は `film.at` / `film.end` だけで書く。ナレーションを作り直しても `build` が秒数を読み直す

### 単調にしない

単調さは、変化の無さと、予想どおりの繰り返しから来る。見る人が次を予想し、予想が当たり、ときに良い方向に外れるように動きを設計する。

- 説明の主役になる名詞は、見える物にする。文字だけの札は補助に回す
- 何かが届いたら、届いた先が変わる。原因と結果を両方見せる
- 止まって見える間も、世界のどこかは生きている

### 抑えるもの

映像の格は、足す物より削る物で決まる。内容がはっきり求めるとき以外は、画面を飾るための効果、意味の無い回転や寄り、
内容と関係の無い飾りを使わない。山場では「音ハメ」の「山場の働き」を優先する。

### 場面を物でつなぐ

境目で全部を消して新しく出し直すと、スライドをめくっているように見える。前の場面に残っている物を、次の場面の物に変えてつなぐ。

- 次の場面でも使う物は section の外（`#stage`）に置き、場面の頭で `film.spot` で新しい位置へ動かす
- 全部を消して出し直すのは、話の章が変わる所だけにする
- `#stage` の物は場面が変わっても消えないので、使い終わったら自分で消す

### 文字を動かす

文字の出し方は、言葉の意味から決める。1 文字ずつ下から立ち上げる道具がある: `film.typeIn(tl, "#t-title", film.at("title", 0.4))`
（文字だけを持つ要素に使う。中の子要素は文字に置き換わる）。字幕と本文は、読む速さを妨げない出し方にする。

### 仕組みを本物で見せる

説明の対象が過程なら、それらしい絵を描く代わりに、小さなシミュレーションを動かして見せる。

- 乱数はシード付きの関数（例: mulberry32）で作り、時刻 t だけで状態が決まるように書く。
  毎回 0 から t まで計算し直してよい（下の「決まった絵になるように」と同じ理由）
- 数字は実際の値を使い、原稿の数字と合わせる。推定の値には「約」を付ける

## 文字

- `<html lang="ja">` と `kit/base.css` で、見出しは文節の切れ目で改行される。長いカタカナ語
  （セキュリティトークンサービス）は途中で割れるので、短い言葉か英語の表記にする
- 文字の大きさは役割から決める。`check` は 24px 未満を止める。数字には `class="num"`（等幅の数字）
- 不透明度を 0.9 未満にした文字（わざと暗くした部品）はコントラストを測らない。読ませたい文字は薄くしない
- 色は `:root` の変数で決め、意味で使い分ける

## 決まった絵になるように

- 動きは `film.build` の中の GSAP のタイムラインか、`film.draw` で書く。CSS の `animation`・`transition`、
  `Date`・`Math.random`・`setTimeout`・`requestAnimationFrame` は使わない
- 同じ時刻はいつも同じ絵にする。`film.draw` の中で前のコマの値を覚えておかない。GSAP で同じ要素の同じ値を
  2 つの動きで書かない（巻き戻すと絵が変わる。`check` が止める）
- 数え上げは `onUpdate` で文字を書き換える（プレーヤーがコマごとに呼ぶ）
- 画像を使うときは `<work>/film/` の中に置き、相対パスで読む

## 効果音

`script.json` の `sfx` の `at` には、その音を鳴らす動きに渡した `film.at(場面, 秒)` の秒をそのまま書く。
例えば `tl.fromTo("#key", …, film.at("problem", 1.6))` に合わせる音は、場面 `problem` の `"at": 1.6`。
効果音を付けた動画は、タイトルの場面に `SFX: 11.ai` を小さく入れる。
